# 管理员创建公司优化 2.0（完整修复方案）

## 0. 背景与目标

目标是把“用户提出创建公司”这一需求，稳定地落到**唯一**的标准落盘流程：

1) admin 先“澄清需求 + 生成配置草案”（不做不可逆操作）  
2) 用户确认草案后，admin 才调用工具 `create_company`  
3) `create_company` 必须按 **draft -> confirm -> apply** 三步完成落盘  
4) 公司创建流程中禁止用 `shell` 执行 `multiclaw instance create/list`、`cat instances.json` 等“先执行后查看”的命令序列（避免工具次数暴涨与审计困难）

本文件用于：  
- 复盘你在控制台中观察到的错误模式  
- 给出 admin 提示词与实现的修复清单  
- 给出验证标准与回归测试点

## 1. 问题复盘（对应你的 1-4 条）

### 1.1 问题 1：使用了错误的工具（实例创建命令）
**现象**：控制台第一轮出现：
`multiclaw instance create assistant --preset startup`

**原因推断**：你当前 `admin` 的提示词里仍存在“创建实例（公司）默认通过 CLI 执行”的规则，导致模型优先选择 `shell + multiclaw instance create`，而不是工具 `create_company`。

**修复方向**：  
1. 在代码侧（`src/entity/mod.rs` 的 `ADMIN_AGENTS/IDENTITY` 常量）移除/覆盖“CLI instance create”公司创建规则  
2. 在运行侧（`~/.multiclaw/instances/admin/workspace/{IDENTITY,S0UL,AGENTS}.md`）同步更新提示词，确保已有工作区也生效  
3. 把“公司创建”作为 **强约束标准流程**写入 admin 提示词，使模型只能走 `create_company` 工具路径

### 1.2 问题 2：创建流程未做用户确认（目标/CEO/团队/资源）
**现象**：你希望的理想流程是：
- admin 问需求  
- admin 生成“公司说明、CEO说明、团队配置、资源约束草案”  
- 用户确认后再落盘  

但你观察到创建过程直接进入 tool 调用（`create_company draft/confirm/apply`），说明 admin 提示词没有强制“先问清楚 + 再让你确认草案”，导致模型把“draft”当作“问答确认环节”的替代品。

**修复方向**：  
1. 在 admin 提示词里加入“公司创建标准流程（强约束）”段落：  
   - 禁止在收到用户确认前调用 `create_company draft`  
   - 草案必须包含：公司目标/用途、CEO 指令要点、团队岗位与分工、资源/额度与 `agent_max` 估算  
2. 草案输出必须带显式确认口径：  
   - 回复 `确认` 才允许进入 `create_company draft -> confirm -> apply`

### 1.3 问题 3：创建中反复查看集群状态/config（也是流程缺失导致）
**现象**：apply 之后 admin 又请求你通过 shell 检查 `instances.json`、workspace 目录等：
- `cat /Users/dragonborn/.multiclaw/instances.json`
- `multiclaw instance list`
- `ls -la ...`

**原因推断**：admin 没有一个“失败处理标准动作”，导致模型用 `shell` 进行自助调试；同时也缺失“当工具失败时应如何复盘/请求你确认”的流程化约束。

**修复方向**：  
1. 在 admin 提示词中加入“失败处理规则”：  
   - 优先复述 `create_company` 的错误信息  
   - 不自动 shell 探测  
   - 仅在你明确授权“需要我手动检查”时，才给出建议命令（仍不自动执行）

2. 在公司创建流程中，admin 的唯一落盘动作为 `create_company`；其余查询由你触发（或在你明确授权后执行）。

### 1.4 问题 4：工具调用超过 10 次
**原因推断**：问题 1-3 的错误模式导致模型反复：
- 用 `shell` 执行 `multiclaw` 和文件检查
- 在错误后又继续探索

**修复方向**：  
修复 1-3 后，标准流程应只产生少量工具调用：
- （通常）`memory_recall`（由模型行为决定，但可通过提示词减少）
- `create_company` 三次：draft/confirm/apply
- CEO/实体落盘相关工具可在公司创建完成后再发生

因此达到“<=10 次”应为可观测、可回归的目标。

## 2. 标准流程（写进 admin 提示词，作为强约束）

### 2.1 公司创建标准流程（必须执行）

当用户表达“创建公司/启动公司/开公司”意图时，admin 必须按下述顺序执行：

1) **需求澄清（不调用 create_company）**  
   需要至少覆盖：  
   - 公司目标（用户要解决什么问题）  
   - 业务范围（做什么/不做什么）  
   - 风格与边界（语气、频率、合规与安全边界）  
   - 资源限制（大致允许多少实体/调用强度，映射到 `agent_max`）  
   - 期望初始岗位包（若用户未指定，则 admin 给出建议岗位）  

2) **生成草案（不调用 create_company）**  
   生成草案并输出（建议结构化）：  
   - `公司说明（IDENTITY + SOUL 关键要点）`  
   - `CEO 说明（CEO 的工作规则、职责边界）`  
   - `团队/岗位分工（entities[]：id/role/team_id/技能约束）`  
   - `资源配置草案（agent_max 估算 + 理由）`

3) **用户确认（必须）**  
   admin 必须显式要求：  
   - 回复 `确认` 才继续  
   - 或回复 `修改：...` 返回修改点并重新生成草案

4) **工具落盘（收到确认后才允许）**  
   严格按：
   - `create_company { action: "draft", ... }`
   - `create_company { action: "confirm", company_id: ... }`
   - `create_company { action: "apply", company_id: ... }`

5) **成功汇报 / 失败处理**
   - 成功：汇报创建结果（实例端口、workspace路径、已创建实体）并给下一步建议  
   - 失败：只复述 `create_company` 错误，不执行 shell 自助探索；请求你确认是否允许“手动检查”。

### 2.2 禁止规则（硬约束）
- 公司创建流程中禁止：  
  - `shell` 执行 `multiclaw instance create ...`  
  - `shell` 执行 `multiclaw instance list/status ...`  
  - 自动读取 `~/.multiclaw/instances.json` 或 `instances/...` 目录
- 在未收到 `确认` 前禁止调用任何会落盘/创建实例的动作。

## 3. 代码与提示词修复清单（实现要点）

### 3.1 代码侧（必须改）
- 修改：`src/entity/mod.rs`
  - `ADMIN_IDENTITY`：删除/替换“创建实例（公司）默认通过 CLI 执行”的描述
  - `ADMIN_AGENTS`：  
    - 移除 CLI 创建实例规则  
    - 增加“公司创建标准流程（强约束）”段落  
    - 增加“失败处理规则（不 shell 自助探索）”

### 3.2 运行侧（必须同步改到你本机已有文件）
- 修改：  
  - `~/.multiclaw/instances/admin/workspace/IDENTITY.md`  
  - `~/.multiclaw/instances/admin/workspace/SOUL.md`  
  - `~/.multiclaw/instances/admin/workspace/AGENTS.md`

原因：`scaffold_admin_workspace()` 只会在文件不存在时写入；你机器上文件已存在，所以必须直接覆盖更新。

### 3.3 工具侧（如果仍出现 apply 失败再处理）
当前 `create_company` 已具备 draft/confirm/apply 三步，但如果 apply 仍失败且报错信息不够明确：
- 才需要增强 `src/tools/create_company.rs` 的错误输出
- 让 admin 能够“复述错误并请求你确认”，而不是退回 shell 探测
