# 改造实施计划 — 阶段 2.5：Tool / Skill 概念对齐、ClawHub 与技能治理

> **依赖**：阶段 2（Entity、实例 workspace、实体级能力约束已存在）。  
> **目标**：与业界 Agent 设计（含 `s_full` / OpenClaw）在 **Tool** 与 **Skill** 语义上对齐；实现与 **[ClawHub](https://github.com/openclaw/clawhub)**（官方 **Skill Directory**，面向 Clawdbot / OpenClaw 生态的公共技能注册表，见 [README](https://github.com/openclaw/clawhub/blob/main/README.md)）可对接的发现与安装能力；建立**安全审查 + 多角色审批 + 实体白名单**的完整技能生命周期。  
> **原则**：每模块需可测；控制面落盘可审计；不混淆「可执行工具」与「领域技能包」。  
> **环境假设**：当前以**测试环境**为主（可删库重来），**不做**「旧配置字段 → 新字段」的兼容迁移；直接采用标准命名与数据结构一次性落地。

## 〇、背景与问题陈述

### 0.1 设计理念对照（`Agent设计核心理念.md` / `s_full.py`）

| 概念 | 业界参考含义（s05 + s02） | 在 `s_full.py` 中的体现 |
|------|---------------------------|-------------------------|
| **Tool** | 模型可调用的**可执行能力**，带 **JSON schema**，由循环 **dispatch → handler → tool_result** | `bash`、`read_file`、`task`、`load_skill` 等均注册在 **TOOLS** 列表中，走同一套 `TOOL_HANDLERS` |
| **Skill** | **领域知识 / 工作流说明**，以文件（如 `skills/<name>/`）形式存在；系统提示中只放**廉价索引**，正文通过 **`load_skill(name)`** 按需注入 | `SKILLS = SkillLoader(SKILLS_DIR)`；`SYSTEM` 里 `Skills: {SKILLS.descriptions()}`；**不**把 skill 正文全量塞进 system prompt |

**关键结论**：Skill **不是** Tool 的子类型；`load_skill` **是** Tool（用于加载 Skill 内容），与 `shell`、`file_read` 并列。

### 0.2 当前实现与规范的差距

| 现状 | 问题 | 目标状态 |
|------|------|----------|
| `[[instance.entities]].skills` / `EntityRuntime.skills_allowlist` | 名称是「skills」，实际存的是 **`Tool::name()` 白名单**（如 `file_read`），与业界「技能包 Skill」混用 | **直接改为标准命名**：`tool_allowlist` + `skill_allowlist`（见 §1.2）；代码与配置**不保留**旧字段兼容 |
| `SKILL.toml` 中 `[[tools]]` | 描述的是技能内**声明式步骤**（shell/http），**未**注册为原生 `Tool` | 文档与 schema 标明为 **「skill-declared actions」**；执行仍通过已有 `shell` / `http_request` 等 **Tool** 完成，或未来由 `skill_run` 统一封装（可选） |
| 无 `load_skill` Tool | 与 s05 两层注入不一致；Compact 模式依赖 `file_read` 读路径 | 提供 **`load_skill`**：参数 `name`，返回经允许的 SKILL 正文（受实体 **skill_allowlist** 约束） |
| `skills/` 目录 | 同时承担「技能包存储」角色，易被误解为「只放 skill」 | 明确：**技能包**落盘于 `.../skills/<skill_id>/`；**与 Tool 注册表无关** |

## 一、概念模型与术语（对外契约）

### 1.1 定义

- **Tool（工具）**  
  - 实现 `crate::tools::traits::Tool`，由运行时注册进 **Provider 的 tools 列表**。  
  - 实体级：**工具白名单**控制「能调用哪些 Tool」。

- **Skill（技能包）**  
  - 社区或本地打包的 **SKILL.md / SKILL.toml** 等内容，位于实例或共享目录下的 `skills/<id>/`。  
  - **不**直接实现 `Tool`；模型通过 **`load_skill`** 或（兼容路径）`file_read` 读取**被授权**的技能正文。  
  - 实体级：**技能白名单**控制「可加载哪些 Skill id」。

### 1.2 配置与数据结构（标准方案，无兼容层）

| 配置键 | 含义 |
|--------|------|
| `entity.tool_allowlist` | 允许的 `Tool::name()` 列表（可执行工具白名单） |
| `entity.skill_allowlist` | 允许 `load_skill` / 技能索引中出现的技能包 **id**（目录名）；与工具白名单完全分离 |
| `[skills]` | 实例/集群级：`open_skills_dir`、`prompt_injection_mode`、`shared_skills_dir`（全局技能库根路径）等 |

**说明**：`skill_allowlist` 可为空，表示「未显式授予任何技能包」；具体授权路径见 **§五、§5.1**。

### 1.3 提示词注入（与 s05 对齐）

| 模式 | 行为 |
|------|------|
| **Index（默认推荐）** | System 中仅列出技能 **id + 一行描述 + location**（廉价） |
| **Full（可选）** | 与现 `SkillsPromptInjectionMode::Full` 类似，全文预载（高 token） |
| **On-demand** | 模型调用 **`load_skill(name)`** 获取完整正文（**必须**校验 `name ∈ 有效且已授权技能`**） |

## 二、ClawHub 官方形态与 MultiClaw 对接

### 2.1 官方仓库与文档（权威来源）

| 资源 | URL | 用途 |
|------|-----|------|
| 源码 | [github.com/openclaw/clawhub](https://github.com/openclaw/clawhub) | 产品实现、Convex、`packages/schema`（`clawhub-schema`） |
| README | [README.md](https://github.com/openclaw/clawhub/blob/main/README.md) | 能力概览、CLI、技术栈 |
| 产品 + 实现 Spec | [docs/spec.md](https://github.com/openclaw/clawhub/blob/main/docs/spec.md) | Skill/Version 对象、搜索、下载 API、审核模型 |
| CLI 与 HTTP 路由 | [docs/cli.md](https://github.com/openclaw/clawhub/blob/main/docs/cli.md) | **与 MultiClaw 适配器直接对应的 REST 路径** |

**官方定义**（摘自 README）：ClawHub 是 **Clawdbot** 的公共技能注册表（`SKILL.md` + 附属文件），支持发布、版本、**向量检索**、审核与 CLI；线上站点 **https://clawhub.ai**；后端为 **Convex**（DB + 文件存储 + HTTP actions）+ GitHub OAuth；搜索为 **OpenAI embeddings + Convex vector search**（详见仓库 `docs/spec.md`）。

### 2.2 与 OpenClaw / MultiClaw 的关系

- **OpenClaw / Clawdbot**：独立运行时；常见布局含 workspace `skills/`；与 ClawHub 通过 **同一套 skill 包格式**（`SKILL.md` frontmatter 等，见 ClawHub `docs/skill-format.md`）衔接。  
- **MultiClaw**：不内嵌 ClawHub 前端；通过 **HTTP 客户端**调用官方 **Registry API**（与官方 CLI `clawhub` 一致），下载 zip 后走本地审计与全局库落盘。

### 2.3 本仓库已有基础

| 组件 | 位置 | 说明 |
|------|------|------|
| 技能落盘与解析 | `src/skills/mod.rs` | `SKILL.toml` / `SKILL.md`、open-skills、审计 `audit.rs` |
| OpenClaw 迁移 | `migrate openclaw` | 可将技能目录拷入 workspace |
| SkillForge Scout | `src/skillforge/scout.rs` | `ScoutSource::ClawHub` 已**枚举**；需改为调用 **§2.6** `ClawHubRegistryClient` |

### 2.4 Registry 基址与官方 CLI 对齐

官方 CLI（`packages/clawdhub`，二进制名 `clawhub`）默认行为（见 [docs/cli.md](https://github.com/openclaw/clawhub/blob/main/docs/cli.md)）：

- **`--registry`**：API Base URL；默认 **`https://clawhub.ai`**（与 `--site` 浏览器登录站点可区分）。  
- 环境变量：**`CLAWHUB_REGISTRY`**（旧名 `CLAWDHUB_REGISTRY` 仍兼容）。

MultiClaw 配置建议与之一致，便于排障与抓包对照：

| 配置键 | 说明 |
|--------|------|
| `skills.clawhub.enabled` | 是否允许调用远程 Registry |
| `skills.clawhub.registry_url` | 默认 **`https://clawhub.ai`**；内网镜像时改为镜像根 URL |
| `skills.clawhub.token` | 可选；只读下载/搜索通常可匿名；与 CLI `config.json` 中 token 同角色时走 secret store |
| `skills.clawhub.timeout_ms` | HTTP 超时 |

### 2.5 公开 HTTP API（与官方 `clawhub` CLI 一致）

以下路径均以 **`{registry_url}`** 为前缀（默认 `https://clawhub.ai`），与 [docs/cli.md](https://github.com/openclaw/clawhub/blob/main/docs/cli.md) 逐条对应；**版本与鉴权细节以仓库内 `packages/schema` 及 Convex HTTP 实现为准**，升级时以适配器单点兼容。

| 能力 | HTTP | 对应 CLI |
|------|------|----------|
| 向量/关键词搜索 | `GET /api/v1/search?q=...` | `clawhub search ...` |
| 列表浏览（最新等排序） | `GET /api/v1/skills?limit=...`（`explore` 等参数见 CLI） | `clawhub explore` |
| 技能元数据与版本解析 | `GET /api/v1/skills/{slug}` | `clawhub install` / `inspect` 解析阶段 |
| 包下载（zip） | `GET /api/v1/download`（与 `install` 流程一致，携带 slug/version 等 query 或 body，**以实现为准**） | `clawhub install <slug>` |
| 身份校验 | `GET /api/v1/whoami` | `clawhub whoami` |

**Spec 补充**（[docs/spec.md](https://github.com/openclaw/clawhub/blob/main/docs/spec.md)）：提供 **JSON 元数据 + 版本列表**；下载接口返回 **某版本的 zip**；软删版本控制下载可见性。MultiClaw **只消费**已通过官方列表/搜索返回的、且 `moderationStatus` 为可安装状态的技能（具体过滤字段以实现为准）。

### 2.6 适配器实现要点（Rust）

```
┌─────────────────────────────────────────────────────────────┐
│ ClawHubRegistryClient（对 `{registry_url}` 封装）            │
│  - search(q)           -> GET /api/v1/search?q=...           │
│  - explore(limit, sort)-> GET /api/v1/skills?...            │
│  - get_skill(slug)     -> GET /api/v1/skills/{slug}         │
│  - download_zip(slug, version|tag) -> GET /api/v1/download  │
└──────────────────────────┬──────────────────────────────────┘
                           │ zip 解压至临时目录
                           ▼
                   audit_skill_directory → 通过则写入 shared/skills/<slug>/
```

**包格式**：zip 解压后须含可解析的 **`SKILL.md`**（及附属文件），与 ClawHub 上传校验一致（见 spec「Upload flow」）；再进入 MultiClaw `audit.rs` **二次策略**。

**离线/内网**：`registry_url` 指向企业镜像时，须提供与上述路径**同构**的网关，或单独实现 `FileMirror` 适配器（仅 dev/test）。

### 2.7 技能存储的两层与 ClawHub 落点

| 层级 | 路径（示例） | 含义 |
|------|----------------|------|
| **实例技能库** | `instances/<instance_id>/workspace/skills/<skill_id>/` | **本实例**已安装、且纳入实例策略的技能包；实体**优先**从此集合与策略中消费。 |
| **全局技能库** | `cluster_root/shared/skills/<skill_id>/` | **集群共享**；凡从 **ClawHub 新引入**的技能，**必须先**经平台安全审计**通过后**写入此处（见 §5.1）；已存在于全局的包视为**已扫描入库**，可优先被检索与复用。 |

**实体是否「可用」某技能 id**：须同时满足：(1) `skill_id` 在该实体的 **`skill_allowlist`**（或创建/实例策略中已等价授予）；(2) 磁盘上存在对应包（§六）。其中 **②③** 路径下新增的 id 必须由 **CEO 批准**后写入 `skill_allowlist`；**①** 若已预置在 `skill_allowlist` 则无需再次 CEO。

## 三、工具（Tool）清单 — 阶段 2.5 新增 / 调整

### 3.1 命名约定（全仓统一 `snake_case`）

| 前缀 | 含义 | 示例 |
|------|------|------|
| `skill_*` | MultiClaw **本地磁盘**技能索引与正文加载（实例 / 全局 / open-skills），**不**走 ClawHub HTTP | `skill_index`、`load_skill` |
| `clawhub_*` | 调用 **ClawHub Registry**（§2.5），行为与官方 CLI **`clawhub`** 子命令一一对应 | 见下表 |
| `ceo_*` | CEO 治理（实体授权） | `ceo_skill_grant` |
| `admin_*` | 集群级运维（可选） | `admin_skill_remove` |

### 3.2 工具一览（对外稳定名）

| `Tool::name()` | 职责 | 与官方 CLI / HTTP 的对应 |
|----------------|------|---------------------------|
| **`skill_index`** | 聚合检索 **① 本实例 workspace** + **② `shared/skills`** 下已存在的技能 **slug/id**（见 §5.1），供模型**先于**远程检索使用 | MultiClaw 自有 |
| **`clawhub_search`** | 远程**关键词/语义搜索** Registry | `clawhub search …` → `GET /api/v1/search?q=...` |
| **`clawhub_explore`** | 远程**列表浏览**（最新/排序等） | `clawhub explore` → `GET /api/v1/skills?...` |
| **`clawhub_import_global`** | 按 **slug** 从 Registry **拉取 zip**（`GET /api/v1/skills/{slug}` + `GET /api/v1/download`）→ 解压 → **MultiClaw 强制审计** → 仅通过则写入 **`shared/skills/<slug>/`** | 对齐 `clawhub install <slug>` 的拉取与解压，**落盘路径**按本方案改为全局库 |
| **`load_skill`** | 按 `name` 返回已授权技能正文（§六 解析顺序） | 对齐 `s_full` 的 `load_skill` |
| **`ceo_skill_grant`** | 将 `skill_id` 授予某实体 **`skill_allowlist`** | MultiClaw 自有 |
| **`admin_skill_remove`**（可选） | 从 **`shared/skills/`** 删除或标记不可用 | MultiClaw 自有；不等价于 Registry 侧 `delete`（软删见 [docs/cli.md](https://github.com/openclaw/clawhub/blob/main/docs/cli.md)） |

**说明**：

- 不再使用 `clawhub_browse`、`clawhub_fetch_and_publish_global`、`skill_search_local`、`ceo_approve_skill_for_entity` 等混用名；文档与实现均以 **§3.2 表内名称**为准。  
- 若需减少 Tool 数量：可将 `clawhub_search` + `clawhub_explore` 合并为 **`clawhub_registry`**（参数 `action: "search" \| "explore"`），HTTP 仍分别调用 §2.5 两路由。

### 3.3 管理员 / CEO 与审计关系

| 能力 | `Tool::name()` | 说明 |
|------|----------------|------|
| CEO 授予实体使用某技能 | `ceo_skill_grant` | 见 §5.1 |
| 集群移除全局包（可选） | `admin_skill_remove` | 本地磁盘；Registry 上仍可能存在 |
| 首次 ClawHub 入库 | 内嵌于 `clawhub_import_global` | **审计不过则不写入 `shared/skills/`** |

### 3.4 不应放入 Skill 的内容

- **ClawHub 查询 / 安装申请** 应为 **Tool**（需审计、限流、权限），**不要**做成仅存在于 SKILL.md 的自然语言步骤，避免绕过策略。

## 四、安全审查机制（平台强制）

### 4.1 扫描时机

1. **ClawHub → 全局库**：`clawhub_import_global` 在**写入 `shared/skills/<slug>/` 之前**必须执行；失败则**不落盘**。  
2. **可选**：对已存在全局包做抽检或版本升级时复扫。  
3. **实例目录**：若后续支持直接写入实例 `workspace/skills/` 的独立入口，须同样先扫再落盘（本阶段默认以 ClawHub→全局为主）。

### 4.2 扫描内容（在 `src/skills/audit.rs` 上扩展）

| 类别 | 示例规则 |
|------|----------|
| 路径与链接 | 路径穿越、可疑 symlink |
| 命令与脚本 | `rm -rf /`、`curl \| bash`、危险 `eval` |
| 网络 | 非允许域名（与实例 `http_request` 策略对齐的可选检查） |
| 元数据 | 与 ClawHub 声明的 checksum / 版本是否一致（若上游提供） |

**结果**：不通过 → **拒绝安装**，并返回结构化原因；**不**仅依赖 LLM 或 CEO 肉眼判断替代平台扫描。

### 4.3 与实体工具白名单的关系

- **工具白名单**仍限制能否调用 `shell` 等；**即使** skills 授权了某工作流，实体若无 `shell` 权限仍无法执行其中 shell 步骤——需在 Skill 文档或 `load_skill` 返回中明确提示。

## 五、端到端流程（创建 → 运行 → 发现 → 安装 → 使用）

### 5.1 实体「可用技能」的获取顺序（核心策略）

**目标**：优先用**本实例已允许**的技能；不足时**先吃**全局已安装（已扫库、更安全）；仍没有时**再走 ClawHub**，且必须**审计→入库全局→CEO 批准**。

| 步骤 | 动作 | 说明 |
|------|------|------|
| **① 优先** | 在本实例策略范围内使用技能 | 仅展示 / 允许加载 **本实例 workspace** 下、且符合实例配置的技能 id（含创建实体时预置、实例级白名单等）。 |
| **② 其次** | 本地不足 → 检索 **全局技能库** | `shared/skills/<id>/` 中的包**均已通过平台安全审计**（入库时扫描），相对更安全；实体侧需 **CEO 批准**后，将该 `skill_id` 纳入该实体的 `skill_allowlist`，方可 `load_skill`。 |
| **③ 最后** | 全局仍无所需 → 搜索 **ClawHub** | 拉取候选包 → **强制安全审计** → **仅**通过后写入 **全局技能库**（`shared/skills/<id>/`）→ **不再**需要「管理员审批落盘」与 CEO 抢跑；随后 **CEO 批准该实体使用该 skill_id** → 进入 `skill_allowlist` → `load_skill` 可用。 |

**ClawHub 与全局库的关系**（本方案固定）：

- 从 ClawHub 引入的新技能：**不允许**跳过审计写入实例目录作为「快捷路径」；**标准路径** = 审计通过 → **全局技能库**。
- 若产品仍需「仅本实例可见」的热修复包，可单独立项（非本测试阶段默认）。

**① 与 CEO 的关系**：`skill_id` 若在**创建实体 / 实例策略**中已写入 `skill_allowlist`（或等价「本实例已允许」列表），则 **`load_skill` 可直接使用**，无需再走 CEO；**②③** 涉及**新授予**某实体的技能 id 时，均需 **`ceo_skill_grant`** 写入 `skill_allowlist`。

```text
创建实体
  └─ 预分配 tool_allowlist + skill_allowlist（可空，含实例内预置技能 id）

运行中需要某领域能力
  ├─ ① 本实例 workspace / 策略已覆盖该 skill_id 且已在 skill_allowlist？
  │     └─ 是 → load_skill
  ├─ ② 实例侧没有 → 全局库 shared/skills 是否已有该 id？
  │     └─ 是 → CEO 批准该实体 → 更新 skill_allowlist → load_skill
  └─ ③ 全局也没有 → clawhub_search / clawhub_explore → clawhub_import_global
        → 审计通过 → 写入 shared/skills/<slug>/
        → CEO 批准该实体 → skill_allowlist → load_skill
```

**状态持久化建议**：`skill_grants` 或 Entity 扩展字段记录：`skill_id`、`source`（`instance` \| `global`）、`security_scan_passed_at`（全局入库时）、`ceo_approved_at`、`approved_by`。

## 六、磁盘加载顺序与解析规则（`load_skill` / 索引构建）

用于 **合并多个来源**时的**解析优先级**（同名 `skill_id` 时）：

| 优先级 | 路径 | 用途 |
|--------|------|------|
| 1（高） | `instance_workspace/skills/<id>/` | 本实例覆盖（调试 / 实例专属变体） |
| 2 | `cluster_root/shared/skills/<id>/` | 全局技能库 |
| 3 | `config.skills.open_skills_dir`（open-skills 只读克隆） | 社区索引（可选；若与 ①② 同名，仍以 ① 为准） |

**去重**：高优先级路径覆盖低优先级；**`load_skill` 授权检查**仍以 **CEO 批准的 `skill_allowlist`** 为准，与路径优先级独立（未授权则不解密/不返回正文）。

**本地检索工具**（`skill_index`）应合并展示：① 实例可见技能 + ② 全局库技能（标注来源与是否已审计入库），便于模型在触达 ClawHub 前先消化②。

## 八、测试矩阵（最低要求）

| 场景 | 测试类型 |
|------|----------|
| `load_skill` 未授权 skill | 返回明确错误，不泄露路径内容 |
| `clawhub_import_global` 审计失败 | **不**写入 `shared/skills/` |
| 全局库已存在 skill | `skill_index` 可发现；无 CEO 批准则仍不可 `load_skill` |
| CEO 未批准 | `skill_allowlist` 不含该 id，`load_skill` 失败 |
| 工具白名单无 `shell` | Skill 内 shell 步骤仅文档提示，执行仍被拒 |
| 同名 id | instance `skills/` 覆盖 `shared/skills/`（§六） |
| 流程顺序 | 先本地+全局检索，再允许调 ClawHub（策略层可测） |

## 十、非目标（本期明确不做或延后）

- 不强制实现 HuggingFace 技能分发（SkillForge 可预留）。  
- 不将 **Skill 内声明式 `[[tools]]`** 自动注册为无限多个原生 Tool（避免攻击面）；若需统一入口，单独立项 `skill_invoke` 并做强校验。  
- 不替代 Clawdbot / OpenClaw 运行时本体；Registry 契约以 **[openclaw/clawhub](https://github.com/openclaw/clawhub)** 的 **`packages/schema`** 与 **Convex HTTP 实现**为准，版本升级时在 **`ClawHubRegistryClient`** 内做兼容。
